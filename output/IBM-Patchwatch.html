Verglichen werden die Versionen aus Ihrer Datei. Eine gleiche Basisversion bestätigt nicht, dass alle Sicherheitskorrekturen und iFixes installiert sind.

Hilfe: Inventar erstellen und Daten aktualisieren
  1. Auf dem IBM-Server den Collector ausführen: python3 ibm_discovery.py --json > inventory.json
    Ohne Datei auf dem Server, direkt vom eigenen Rechner: ssh SERVER 'python3 - --json' < ibm_discovery.py > inventory-SERVER.json
  2. Die Datei nach Windows übertragen und über Inventar öffnen laden oder auf die Seite ziehen. Inventar und Katalog können gemeinsam abgelegt werden.
  3. Nach Produkt oder Status filtern. Voraussetzungen und iFix-Details lassen sich in der jeweiligen Zeile aufklappen.
  4. IBM-Link öffnen, bei Bedarf anmelden und das Paket manuell herunterladen. Die Ansible-Installation wird separat gestartet.

Alle fertigen Dateien liegen im Repository im Ordner output/. Für neue Stände das aktuelle Paket herunterladen oder über Katalog aktualisieren eine neuere catalog.json öffnen. Neue fachliche Hinweise benötigen auch eine neue HTML-Datei.

Beim Schließen der Seite werden die geladenen Inventardaten verworfen. Es erfolgt kein Upload und kein automatischer Zugriff auf den IBM-Server.

Einige Provider prüfen eine versionsgebundene IBM-Seite. Ein neuer Abruf beweist nicht, dass es keine neueren Releases gibt. Fachliche Hinweise und Paketbestätigungen behalten ihr eigenes Prüfdatum.

Installation per CLI ohne Rückfragen (unattended)

Die Seite installiert nichts. Nach dem manuellen Download startet Ansible die Installer still (Response-Dateien, -y, -i silent) auf genau einem Zielserver pro Aufruf. Details: ansible/INSTALLATION.md.

  1. Einmalig den Controller einrichten (Python 3.12 auf Controller und Ziel): cd ansible && python3.12 -m venv .venv && . .venv/bin/activate && python -m pip install -r requirements-controller.txt
  2. Pakete bei IBM manuell herunterladen und auf dem Controller in /srv/ibm-updates ablegen.
  3. Konfiguration anlegen und anpassen (Server in private/hosts.yml; in private/install.yml Installation, Benutzer, Dienste, Response-Dateien und Prüfbefehle): mkdir -p private && cp -R inventories/example/. private/ && cp examples/install-was.yml private/install.yml
  4. Pakete lesend zuordnen (ändert nichts): ansible-playbook -i private/hosts.yml playbooks/scan_patches.yml --limit HB_TEST -e ibm_patch_directory=/srv/ibm-updates
  5. Installieren (läuft tatsächlich, ohne weitere Freigabe): ansible-playbook -i private/hosts.yml playbooks/install_patches.yml --limit HB_TEST -e @private/install.yml

Vorher Backup sicherstellen und selbst über before im Auftrag anstoßen: Die Rolle erzwingt kein Backup. --check wird abgelehnt (kein Probelauf). Bei einem Fehler bleiben Sperre und Laufverzeichnis erhalten; Dienste können gestoppt sein, es gibt keinen automatischen Neustart. Nie beide Produktionsumgebungen gleichzeitig aktualisieren.
